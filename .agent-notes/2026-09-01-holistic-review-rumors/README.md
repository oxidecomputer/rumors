# Holistic review of the rumors crate

This note reviews the `rumors` crate at commit `9e5784fb4dce977cfbdfd1619886d1482b5ce764` (a clean tree): every file under `src/`, `tests/`, `benches/`, and `examples/`, together with `Cargo.toml`, the derived `README.md`, the `justfile`, the `tools/` linters, the CI workflow, and the nextest and mutants configuration. The sibling crates under `crates/` (`before`, `before-fuelscape`, `before-viz`, `rumors-tracing`, `suanpan`, `surface-scan`) are outside the review except where `rumors` uses them, and their sources were read only to settle a claim about `rumors`. No benchmark was run and no performance figure in this note is a measurement. The one full test-suite run was timed on a machine carrying other load (a one-minute load average rising from 9.65 to 19.09 during the run), so its wall-clock figures are indicative only.

## Verdict

The production code is in good shape, and the review found no defect in it that a conforming peer reaches. Across the twenty-six partitions no panic is reachable from wire bytes, payload bytes, bookmark bytes, or storage failure; every wire-facing parser is total over its input; each `expect` and `unreachable!` in production code carries a one-line argument that holds against the surrounding lines. The contracts that matter are carried by the types rather than by prose: the `Peer`/`Rumors` XOR, `Batch` closed by the borrow checker with two `compile_fail` doctests pinning its escape routes, `Encoded::write_with` making wire-before-publication the only order the API admits, and the `yield_resolve_query!` macro binding the publication order the deadlock-freedom argument rests on. Two production findings are the exceptions. `framing::resume_payload` promises `read_payload`'s exactness but lets `read_buf` fill a caller buffer's spare capacity, so the codec's over-budget lone-record path can consume the next frame's bytes (demonstrated; a conforming encoder cannot produce the triggering record, and the one production caller escapes by a single byte of `Vec` minimum capacity). The routed adapter's single `pending_headers` bound evicts a pooling dialer's admitted idle connections before a stalled fresh header, a liveness failure reachable at four pooling peers under the default `Config` (demonstrated on the in-memory network: under `pending_headers: 1`, one stalled arrival evicted the pooled connection and the next stream open on a healthy link failed with `BrokenPipe`; the TCP-pool hang variant and the four-peer figure under the default `Config` are assessed by tracing; owner-gated on whether pooling dials are a first-class deployment shape). Two more production findings sit outside the peer-reachable framing: a destructor-under-lock deadlock a user's `Drop` can reach (async-hazards-3, demonstrated through the public API: a `redact` whose payload destructor called `snapshot()` on the same replica had not returned after ten seconds) and a docs.rs build failure from `doc_auto_cfg` (deps-3, demonstrated).

The largest theme is prose and instruments left behind by mechanical passes that each stopped one step short of their own remainder. The V1 retirement (368da2a5) left seven public sites and a `Display` string telling the user to "select" a `Protocol` no API selects, a `SessionStats` doc announcing two boundaries and listing one, the `Levels` zipper in comments and a test module doc, and V1 phase names in wire-snapshot testdocs. The CBOR respelling of the wire (4dd2053c) left a 25-byte preamble, a two-frame greeting, a one-byte epilogue marker, and "17-byte" records in testdocs whose bodies were updated beneath them, and `28 + m` in two window suites where the crate ships 43. Version addressing (961f63c6) left "content-addressed" generators; height and item erasure left type parameters with one instantiation, hand-written impls that derives now produce, and bounds nothing consumes. The documentation document holds 313 findings, 258 of them verified against the code, and their reach is broad because each pass edited the code precisely and the prose beside it not at all. The same pattern produced the hand-maintained numbers that have rotted: the geometry fixture's "attempt 1581" measured under BLAKE3, `reconciliation.rs` deriving the stream bound as sixteen data streams plus control against `STREAM_COUNT`'s seventeen, `parking.rs`'s megabyte figures two format changes behind their own pin.

The second theme is verification instruments that read failure as success, or that never run. Three of the review's eleven high-severity findings are correctness defects in test infrastructure: the streaming capacity probes collapse protocol violation and poll-budget exhaustion into "did not stall"; the inter-process disruption parent never joins its serving tasks, so a panic there changes the loss accounting with no failing assertion; and the capture renderer elides container-shaped map keys to `…`, so two wire byte strings can render identically under a module doc that rests the snapshot discipline on injectivity. The seven verification highs are of the same kind: the bookmark-causality recycle oracle flags only the degenerate recycle while the one the bookmark exists to prevent deletes a durable message fleet-wide unobserved; the backend census ceiling and `window_census` both difference two identical runs because a 64 KiB budget resolves to the all-ones floor window; the leaf-height deletion verdict in `materialized::unknown` has no test that fails when inverted; no frame crosses a link on a logical stream with index two or higher anywhere in the crate; `tests/future_size.rs` is compiled out of every committed check. Beside these sit instruments nothing schedules: the envelope simulator that `window.rs` names as the certificate of its 2^-40 bound, `tradeoff_probe`, a mutation campaign last run on a tree predating the codec rewrite, a coverage pin scoped to `before` alone, and a `testdoc` regex that does not match `#[pollster::test]`. Eighteen of the nineteen constructions the review built and ran (fourteen in the first witness pass, five in a second pass after the completeness critic) demonstrated the finding they targeted; the nineteenth refuted a prediction while confirming its kernel.

The third theme is duplication where a shared helper should stand, most of it in the test harness. The bootstrap fork is written ten times across the integration and bench binaries, the retire driver four times, `send_random` seven, the `(hash, latest)` fingerprint twelve, a 64 KiB `LINK_BUF` ten, and the payload-codec constructor sixty-seven times crate-wide; the copies have drifted (one bookmarked join skips the control-drain check every other driver runs, and the measurement fixtures run under `pollster` without the stall detector the shared drivers use). A blanket `#![allow(dead_code, unused_imports)]` on `tests/common` hides two dead imports, a dead field, and a no-op statement, and `tests/common` compiles forty-two times across sixty test binaries. In production the duplication is smaller and structural: three observers re-spell one `Channel` state machine, `gossip_inner` hand-builds eleven `(Intent, Err(..))` tuples because its return type defeats `?`, `read_early` re-implements `read_reply`'s frame loop with a verbatim five-line comment, the proxy elects the initiator a second time and reconciles the two elections with two `unreachable!`s and four `debug_assert_eq!`s, and two single-item upward imports fold eight top-level modules into one dependency cycle. The API document's fifty-six findings are all owner-gated by nature: `#[derive]` on `Error<B>` and `Snapshot<T>` imports bounds their representations never use, `Snapshot::iter`'s type is unnameable, `Bookmark::store` asks implementors for a higher-ranked closure over a trait-object writer to receive a `Vec` the crate has already encoded, many `rumors::error` variants and fields have no doc and no lint notices, and the rule deciding which enums are `#[non_exhaustive]` lives only in a commit message. The scratch application the fresh-eyes sweep wrote from the public docs alone compiled on its first `cargo check` except for two deliberate probes, which is the strongest evidence in the note that the public surface is usable as documented.

Several things the review could not settle. Whether the inverted leaf-height verdict (materialized-27) survives the whole committed suite was not re-run; the construction shows the arm is discriminable, and the handoff note's survival claim stands as reported. The routed-adapter eviction (link-28) was demonstrated on the in-memory network, never driven against a live TCP pool. Whether the two unbiased `tokio::select!` sites in the streaming mirror make `bookmark_causality`'s schedule nondeterministic beyond the `OsRng` network ids is plausible and undemonstrated. Whether `future_size`'s three budget tests pass today is unknown, since no committed check has ever run them. Whether "attempt 1581" still wins under SHA3-256 was not recomputed. The compile-time cost of compiling `tests/common` forty-two times is unmeasured, and every performance candidate in the note is a code reading with no baseline. The crate-wide vocabulary and lint rulings, the public-API reshapings, and the gate-policy questions are gathered under Owner decisions; the review states a recommendation for each and decides none.

## Owner decisions

Every owner-gated finding and every open question the six documents raise, consolidated across documents and grouped by topic. Each item names the finding ids that carry the evidence and ends with the recommendation the documents converged on; where two documents recommend different things, both positions are stated.

### Crate-wide conventions and lints

1. **`pub` versus `pub(crate)` under the private `tree` module** (inventory-10, module-graph-12, tree-typed-1, streaming-backend-window-2, materialized-6, mirror-common-20, session-bookmark-44, api-audit-14). About a hundred `pub` items live in modules no public path reaches, so `pub` no longer marks API and rustdoc for external readers accumulates on unreachable types such as `Message`. The documents recommend enabling `#![warn(unreachable_pub)]` and following every diagnostic (a campaign, since the lint fires on every unreachable `pub` item), or else recording the pub-in-private convention in AGENTS.md and reconciling `typed.rs:19-22` with it; the recommendation is the lint.
2. **A `[lints]` table** (clippy-pedantic open question, api-audit-12, api-audit-7, api-core-34, tree-core-5). The documents recommend adopting `elidable_lifetime_names`, `redundant_closure_for_method_calls`, `manual_let_else`, and `match_wildcard_for_single_variants` at `warn` (zero false positives in the one clippy run), plus `missing_debug_implementations`, `unnameable_types`, and `missing_docs`; each rides the existing `-D warnings` gate and closes a class this note lists by hand.
3. **Em-dashes in `//` and `#` comments** (prose-hygiene-9, prose-hygiene-8, session-bookmark-6, conformance-19, and sixteen further entries; 169 `.rs` comment lines, 159 of them under `src/` and `tests/`, and 95 config-file comment lines). The documents recommend ruling once, sweeping mechanically with the greps recorded in prose-hygiene-9, and adding a `tools/` check on U+2014 in non-doc comment lines wired into `just gate`.
4. **"seam" and "knob" crate-wide** (prose-hygiene-10, mirror-common-34, conformance-22, session-bookmark-5, fresh-eyes-11). "seam" appears on 66 lines (47 in rustdoc, four on public items) with no definition and three distinct referents; "knob" on 46. The documents recommend one sweep following the `mint` purge precedent, writing "boundary" and "setting" in public rustdoc now regardless.
5. **"honest", "lie", and their cousins** (conformance-32, remote-proxy-tests-14, tests-common-23, session-bookmark-16, tests-resource-link-window-6). "honest" is the model of record's term for the trust premise and is borrowed for six other predicates, including `HONEST_LEN`, `Knob.honest`, `Dishonest`, and `is_honest_error`; "lie" and `GreetingLie` presuppose intent the model excludes where 408ede87 already chose "misdeclared". 7. **Import grouping** (tests-wire-format-10 and the import-hygiene pattern, 22 sites). The documents recommend adopting `group_imports = "StdExternalCrate"` if moving `fmt-check` to the pinned nightly is acceptable, otherwise one hand sweep now.

The simplification document recommends moving all six to sibling files, since each is a pure move and a rule without exceptions is the one a checker can enforce; the documentation document's open question 22 proposes exempting test-only scaffolding modules in AGENTS.md instead.
9. **Which layer of `type_complexity` allow to keep** (inventory-3, materialized-8, mirror-common-29). Twelve per-item allows sit under the module-wide allow at `streaming.rs:43`. The documents recommend keeping the module-wide allow and deleting the item-level ones.

### Public API shape and contracts

15. **`Snapshot::iter` and the unnameable `Iter`** (tree-core-5, fresh-eyes-4, inventory-1, api-audit-2, api-core-34). The api document recommends re-exporting `Iter` at the crate root, returning it by name, and enabling `unnameable_types`; the simplification document recommends the reverse, deleting the `IntoIterator` impl and the `pub use` so the opacity 8dc0596ed chose is complete. The two positions are incompatible; the api document's position is the one that also closes the class mechanically.
16. **`Snapshot: PartialEq`** (api-core-35). `==` includes the causal ceiling while `hash()` documents excluding it. The documents recommend documenting `==` as same network, same live set, and same frontier rather than dropping the impl.
17. **The `Bookmark` trait's shape** (session-bookmark-23, api-audit-4). The documents recommend an owned `Vec<u8>` parameter for `store` with `Serialized` deleted, `type Error` folded into `Bookmark` with `BookmarkError` deleted, and `load` kept reader-shaped, in one pre-release edit.
18. **The depth of `rumors::error`** (api-audit-13, api-audit-14, remote-codec-30, remote-codec-28, remote-proxy-2, remote-proxy-3, remote-codec-9, remote-adapter-streams-19, mirror-common-10, api-core-7). The documents recommend treating the codec, adapter, stream, and proxy taxonomy as diagnostic surface: constructors and schedule helpers `pub(crate)`, `signal::StreamError` renamed, `Display` impls that do not route through `Debug`, a concrete `MirrorError` constructed at `streaming_error` so the `Infallible` arms and the dead `PayloadDepthMismatch` arm disappear, `GreetingError::Order` deleted, and the local-versus-peer origin stated on `RemoteError`. In the same pass: typed `Head { part, source }` and `InvalidListing(ListingIssue)` variants in `DecodeErrorKind` (remote-codec-9); infallible `ReplyFrame` constructors with `ReplyFrameError` deleted (remote-adapter-streams-19); `Preamble::decode` over `[u8; V2_PREAMBLE_LEN]` with the two defensive `PreambleDefect` variants dissolved, which reopens ruling R2 on the new fact that `Staged::buf` is now that array (mirror-common-10); and recording the flat-shape decision in `Error::widen`'s doc rather than reshaping the generic error (api-core-7).
19. **`seed_rng` and `warm_caches`** (api-audit-15, api-core-11, api-core-12, inventory-4, benches-envelope-6, tests-lifecycle-10, deps-5, async-hazards-4, tests-bookmark-8). Both are `#[doc(hidden)] pub` with no feature gate while their siblings are gated. The reports disagree: the inventory sweep would un-hide `seed_rng`; three reports would gate both; the wire-format partition would keep `seed_rng` hidden and offer a documented constructor taking a `Network` value, since a caller-supplied RNG can create two universes sharing `Party::seed()`. The documents recommend gating both now (a private inner function lets `seed` keep calling it), adding the `Network`-taking constructor with the two-universes hazard stated on it if application test suites need deterministic ids, using `seed_rng` from the bookmark suites regardless, and, if pre-paying the first greeting's materialization matters to a user, giving `warm_caches` a documented name with its cost stated.
20. **`Rumors::send` returning the `Version` it stamped** (tests-common-2, tests-lifecycle-31). The documents recommend keeping the ruling at `src/rumors.rs:190-203`, adding the recovery idiom (`snapshot().range(causally::since(&pre))`) to `send`'s docs, and consolidating the harness onto `created_version`.
21. **Direct readers** (benches-envelope-19, api-audit open question). The documents recommend adding `Snapshot::versions()` and `Snapshot::contains(&Version)` and leaving `Rumors` reading through a snapshot, saying so in the type doc.
22. **Observability** (session-bookmark-38, remote-adapter-streams-21, materialized-2, remote-codec-5, api-audit-11, link-21, link-16, session-bookmark-20). The documents recommend now: a `SessionObserver::finished` hook carrying the outcome, `frames_sent`/`frames_received` counters, a getter for the effective run budget with `MAX_RUN_BUDGET_BYTES` re-exported, the three settings in `Peer` and `Rumors` `Debug` output, and `(LinkInfo, RoutedLink)` from `Endpoint::link`; a `window_stalls` zero-versus-nonzero readout; router counters only after link-28 lands.
23. **`conformance::bookmark`, hang attribution in `check`, and the cancellation probe's connect precondition** (conformance-1, conformance-6, conformance-37). The documents recommend shipping the bookmark suite with a negative control (a bookmark that commits a partial frame on `Err`) and a paragraph naming what it cannot see, documenting on `check` that a hang under the caller's timeout names no check, and stating in the suite's requirements, rather than as a new contract clause, that the cancellation probe needs two opens to complete while the peer's acceptor is unpolled, since the protocol's own acceptor loop never needs that backlog.

## How this review was done

The crate was split into twenty-six partitions along module boundaries: seventeen over `src/` (including the crate's own test modules), seven over `tests/`, one over `benches/` and `examples/envelope_sim.rs`, and one over `examples/swarm.rs`. Every partition file was read in full with line numbers, about 89,100 lines counting each partition's own files once, plus the out-of-partition context each finding depends on and the pinned sources of dependencies where a claim turned on library behavior (tokio 1.52.3, bytes 1.11.1, ciborium 0.2.2, smallvec 1.15.1, tinyvec 1.11.0, proptest 1.11.0, criterion 0.5.1, static_assertions 1.1.0, and the 1.97.1 standard library). Data and derived artifacts in the tree were read through the code that generates or checks them rather than as roster members of a partition: the `.snap` pins under `tests/snapshots/` and `src/**/snapshots/` through the `insta` tests that produce them and `tests/snapshot_liveness.rs` (tests-wire-format, remote-capture-atlas, session-bookmark), and `src/tree/mirror/streaming/window/tradeoff.md`, which `just window-tradeoff` generates from `examples/window_tradeoff.rs`, through that example (benches-envelope) and the findings that cite it (streaming-backend-window-26, testing-infra-2, api-audit-9). `tests/common/schedule/events.rs` belongs to the tests-common partition and is anchored by tests-common-21, though that partition's roster sentence does not name it.

Each production partition was read independently through four lenses, each by its own agent: structure (module boundaries, duplication, dead machinery, idiom), prose (rustdoc and comments against the code and against the writing doctrine), correctness and verification (panic sites, contract clauses, blind spots in the tests that cover the partition), and performance and API (fixed-sign deletions, resource trades, the public surface). Each test partition was read through three lenses: structure and prose, blind spots (what the suite cannot see, by white-box construction of the shapes each operation maximizes), and API friction and economics (what the harness had to work around, and what each test costs to run). One lens did not finish in the main run: the conformance partition's correctness reader hung, and that partition was finalized from its other three lenses. The lens was rerun after finalization; its candidates went through the same refutation and history passes, none needed or received a construction, and the six survivors (conformance-37 through conformance-42) were merged into the partition report and the topic documents as if the lens had run on time, with the partition report recording that it did not.

Ten cross-cutting sweeps read the whole crate along one axis each. The api-audit sweep rendered the rustdoc with `cargo doc` and walked every public item, impl header, and re-export. The async-hazards sweep read every `async fn`, `select!`, lock acquisition, and `Drop` for cancellation, wake, and lock-hold hazards. The clippy-pedantic sweep ran clippy once with `-W clippy::pedantic -W clippy::nursery`, classified the 2383 diagnostics (1103 in scope) by lint, and read each class against the doctrine. The deps sweep read every manifest and the lockfile, checked each dependency's features against its use sites, and ran `strings` over the pinned rustc's dylibs to settle one docs.rs feature question. The fresh-eyes sweep wrote a 527-line application from the public documentation alone, without reading the source; it compiled on its first `cargo check` except for two deliberate probes (`error[E0603]` on the private `snapshot::Iter`, `error[E0599]` on a `.protocol()` setter that does not exist), and its TCP session completed. The inventory sweep ran scripts over the 113 production files and cataloged 39 lint allows, 88 panic sites, 92 `as` casts, and every visibility modifier. The module-graph sweep ran a script over 183 files to build the module dependency graph, its strongly connected components, and the re-export layers. The prose-hygiene sweep ran greps for the doctrine's lexicon (em-dashes on 1394 rustdoc lines, 169 `//` lines, and 95 `#` lines; "seam" on 66 lines; "knob" on 46), for roster tags, and for dated language. The suite-economics sweep ran `cargo nextest run -p rumors --all-features` once (836 tests in 60 binaries, 22.07 s wall, per-test sum 295.142 s, under external load) plus one run of the `future_size` binary (0 tests), and read the per-test timings against what each test proves. The verification-infra sweep read the justfile, the CI workflow, `.config/nextest.toml`, `.cargo/mutants.toml`, and every `tools/` script, ran `tools/testdoc` against a scratch probe, and read the recent CI runs through `gh run list` and `gh run view`.

Every candidate finding then passed two verification passes, each by an agent that had not written the candidate. The refutation pass was briefed to dispute, not confirm: it re-read every cited line, re-ran every grep, and either confirmed the finding, reframed it (narrowing or widening the claim and adjusting the severity), or dropped it, recording the evidence either way. The history pass ran read-only git (`log`, `blame`, `show`, `log -S`) on every anchored site and classified each finding's provenance: deliberate and holding, deliberate but expired, no rationale found, already known (recorded in an agent note or ruling), or contradicting a hard rule. A finalizer per partition then merged the lens reports and both passes into one report in a fixed template (where, class and severity and confidence, provenance, who saw it, owner-gated or not, the claim, verbatim evidence, the resolution with its acceptance criterion, and a construction where the finding is a gap), dropping candidates the passes did not sustain.

Fourteen findings whose claim rested on a construction were built and run by three agents in isolated worktrees (`.claude/worktrees/wf_866cfd1a-b96-193`, `-194`, `-195`), each applying a reversible mutation or a new test, running the named test with `cargo nextest`, restoring the worktree to HEAD, and verifying `git diff` empty before reporting; the build directories were then deleted and the run logs kept under the scratchpad. Thirteen constructions demonstrated their finding; one (conformance-24) refuted the finding's prediction that a `parent` fault escapes conviction, while confirming that the `Backend` doc's by-name conviction claim is false. Two more runs were made by refutation agents to settle specific points: `window_census` under `--no-capture` (the identical peaks at budgets 0 and 65536), and the three proxy trace tests at `PROPTEST_CASES=1024`.

A second witness pass ran after the completeness critic named five constructions that were cheap and unexecuted: tests-bookmark-12, conformance-28, remote-proxy-tests-10, async-hazards-3, and mirror-common-3, in one further worktree (`.claude/worktrees/wf_8986b141-8e4-2`) under the same restore-and-verify discipline, its results appended to `witness/results.md` under `## Second pass`. All five demonstrated their finding. Two outcomes changed the note beyond a provenance line: async-hazards-3's construction hung (`redact` had not returned after ten seconds because the payload's destructor called `snapshot()` under the commit's write lock), which raised that finding to high; and remote-proxy-tests-10's proposed closing test failed for a reason neither of its branches named, because the deep fixtures place leaves at hand-picked paths that violate version addressing and the wire correctly refuses them, so the gap stands and needs a different vehicle.

Six writers then synthesized the twenty-six partition reports and ten sweep reports into the six topic documents, each carrying every finding of its class with the finalizers' text, lightly edited for style, and a synthesis note where documents overlap; this README was written last from the six documents, the index, the map, and the construction results.

The review executed one clippy run, one `cargo doc`, one full nextest run plus one `future_size` run, the scratch application's `cargo check` and its run, `tools/testdoc` on a scratch probe, the nineteen constructions (fourteen in the first witness pass, five in the second), the two refutation-pass runs, the python regex check of `testdoc`'s attribute pattern, and `strings` over rustc's dylibs. Everything else in this note is by reading, grep, and read-only git. No benchmark, mutants campaign, or coverage run was performed; every performance statement is a code reading.

## Reading the note

The disposition of every finding lives beside this note: `TRIAGE.md` states the phases, lanes, and dispositions, `triage/ledger.tsv` carries one row per id, and `triage/rulings.md` records each decision. The topic documents below are the evidence and are not amended as rulings land.

The note is one directory. `README.md` is this document. The six topic documents each open with an introduction, a highest-value list of at most twelve items, and the crate-wide patterns, then carry every finding of their class grouped by module in crate order: `correctness.md` (26 findings: production defects and test-infrastructure defects that mask failures), `verification.md` (203: gaps in what the tests can see and defects in test quality), `documentation.md` (313: prose that contradicts the code, has lost its referent, or sits at the wrong altitude), `simplification.md` (358: structure, duplication, dead machinery, idiom), `performance.md` (31: fixed-sign deletions, trades to measure, and cost of the suites), and `api.md` (57: surprises in the public surface and capability gaps). `evidence/partitions/<key>.md` holds the twenty-six finalized partition reports, each with its summary, positives, open questions, and dropped candidates; `evidence/sweeps/<key>.md` holds the ten sweep reports; `evidence/map.md` is the orientation map (layering, one gossip session end to end, the invariants, the oracles, the module graph, a glossary, and the public surface); `evidence/witness.md`, when present, holds the nineteen constructions (fourteen from the first witness pass, five from the second) with their commands, output, and cleanup.

A finding id is `<partition or sweep key>-<n>`, where the key names the report that filed it (`tree-core-27`, `deps-3`) and `n` is that report's own numbering. Ids are stable across every document; a finding appears in one topic document and is cross-referenced from the others by id. The severity scale is high (a production defect a conforming peer reaches, or a check that passes on a wrong artifact), medium (a defect or gap with bounded consequence, or a contract the code contradicts), low (accurate but improvable, or a narrow gap), and nit (mechanics, spelling, idiom). Each entry names its provenance: demonstrated (constructed and run in a worktree), verified (a grep, a read of the cited lines, a git command, or a run whose output is quoted), or assessed (by reading and reasoning). Each entry also records whether it is owner-gated, meaning it reopens a recorded ruling, touches public API or wire format, or is the owner's own wording.

Read a topic document's highest-value list first, then its crate-wide patterns, then follow ids into the by-module sections; the evidence files carry the lens reports' original text, the refutation and history verdicts, and the dropped candidates when a finding's history matters. The counts in each document's Counts section count entries, not distinct defects. Where one defect was filed under several ids with no evidence the others lacked, the topic document keeps one entry of record and reduces the others to a one-line cross-reference under their own heading, which is not counted: `tests/future_size.rs` is carried by tests-wire-format-26 (verification-infra-1 and suite-economics-1 refer there), `static_assertions` by deps-1 (inventory-2), the inline test modules by module-graph-6 (mirror-common-22 and suite-economics-11), `DEFAULT_TARGET_MESSAGE_SIZE` by module-graph-2 (materialized-10), and the truncating `as u8` at header.rs:254 by link-25 (inventory-18). Entries that overlap only in part keep their own count and name the entry of record in a synthesis note (api-core-9 and deps-1; link-3 and remote-codec-3; tests-disruption-handshake-31 and tests-resource-link-window-22; testing-infra-5 and module-graph-6). After that folding the eleven high-severity entries are eleven distinct defects. The Module quality map above counts by partition report, where every partition's own entries stand, so it and `evidence/index/counts.tsv` still count a folded duplicate under each report that filed it. Twenty entries file the em-dash-in-line-comment class per partition: eighteen nit rows (session-bookmark-6, conformance-19, tree-core-15, streaming-backend-window-7, materialized-38, remote-adapter-streams-7, remote-proxy-tests-19, tests-common-24, swarm-example-11, prose-hygiene-9, streaming-tests-4, remote-proxy-5, testing-infra-14, tests-bookmark-10, tests-disruption-handshake-13, tests-observation-33, tests-resource-link-window-23, tests-wire-format-13), one low for the assert strings (prose-hygiene-8), and remote-adapter-tests-18 in part; they are counted in the totals, and owner decision 3 above is the one ruling that decides the class.

## Limits

The review read the code and ran almost none of it. No benchmark was run, so every performance statement is a reading with no baseline and no sign measured; the constructions in `performance.md` name the bench each candidate should be measured with. No mutation campaign, coverage run, or fuzzing was performed, and the review's own statement that the mutation campaign's tree predates the codec rewrite is from reading the campaign's notes. The one full test-suite run was timed under external load and its wall-clock figures are indicative only; the per-test critical path it names (the 19.9 s capacity test) is stable enough to act on, the rest is not.

Several findings were traced rather than executed, or executed only in part: the routed adapter's pooling eviction (link-28) was demonstrated on the in-memory network, where one stalled arrival under `pending_headers: 1` made the next stream open on a healthy link fail with `BrokenPipe`, and never driven against a live TCP pool, so the hang variant and the four-peer figure under the default `Config` rest on tracing; whether the inverted leaf-height verdict (materialized-27) survives the whole committed suite was not re-run, only the construction that discriminates it; the destructor-under-lock hazard (async-hazards-3) was reproduced with a re-entrant `Drop` in the second witness pass (a hang, not a panic; that std's `RwLock` does not diagnose the re-entry is assessed, not verified); the nondeterminism of `bookmark_causality` under tokio's unbiased `select!` is plausible and undemonstrated. Whether `future_size`'s three budget tests pass today is unknown to the review as it is to the gate. The hand-maintained "attempt 1581" was not recomputed under SHA3-256. The compile-time cost of compiling `tests/common` forty-two times is unmeasured, and the layout recommendation depends on it.

The sibling crates `before` and `before-viz` were read only where a `rumors` finding turned on them (`Version`'s order, `Party::join`, `codec::canonical_eq`, the skyline literal); nothing in this note is a finding about them. The `formal/` Lean sources were read only to check the citations the code makes; `.agent-notes/`, `design/`, and `results/` were read only where a finding's provenance or a ruling depended on them, and the note does not claim to have audited those trees. The docs.rs configuration was checked under the pinned nightly only; no other toolchain, platform, or network was exercised, and the routed link's TCP behavior was read, not run, on this machine.

The review did not settle taste. Every item under Owner decisions carries a recommendation and no decision; where two documents disagree (the `Snapshot` iterator, the inline test modules, `seed_rng`'s visibility), both positions are stated and the disagreement is the finding. The agents that wrote the note were themselves under completion pressure; the refutation and history passes, the constructions, and the dispute-the-seeds brief exist to bound that, and the remaining residual is that a finding marked assessed rests on one careful reading rather than on a run. Counts are as the documents report them and count entries: 988 entries across the six documents (high 11, medium 157, low 479, nit 341) after five cross-lens duplicates were reduced to cross-references, and the eleven high entries are eleven distinct defects; `evidence/index/counts.tsv`, which counts every partition and sweep report's own entries, holds 995 (high 12, because it counts both `future_size` duplicates beside async-hazards-3). Partial overlaps that the synthesis notes name are still counted once each. The six conformance entries the rerun correctness lens added (conformance-37 through conformance-42) are verified or assessed only: neither witness pass constructed them.

Paths written as `<session scratchpad>/...` in the evidence files name run logs and scratch tests kept in the review session's scratch directory, which is not committed; the witness file quotes the decisive output of each run, and the worktree paths it names were removed after the runs.
